# Meta production-origin isolation

## Scope and baseline

Base: `477f49b8ced37ad2b659178f221bf481a2be7b19`. September 11 read-only Events Manager inspection of NuVira pixel `719023677458304` showed PageView samples from `app.base44.com` and a preview domain alongside the public website. Source inspection confirmed the browser pixel lacked an approved-origin check. C01's correct product links and pixel assignment were separately verified; its missing attributed landing-page views have no established root cause.

This change is **web-only Meta measurement isolation**, not a checkout, consent-policy, attribution-model, ad, or native feature change. Only `src/lib/metaPixel.js` changes application behavior.

## Behavior

- Allow consented, top-level HTTPS visits to `nuvirajuice.com`, `www.nuvirajuice.com`, and the exact published fallback `nuvira-fresh-flow.base44.app`.
- Block the live Meta loader, events and attribution context on editor, preview, local, unknown, malformed and framed contexts. All iframes are intentionally excluded, including a published site embedded in an editor.
- Preserve the narrower apex/www server-relay and custom-cookie allowlists. The fallback site remains browser-only.
- Recheck runtime eligibility after asynchronous work. Consent withdrawal and revocation remain usable in previews.
- Keep shared Snapchat context/consent helpers, Google tracking, native exclusion, Stripe-authoritative Purchase and customer checkout unchanged.

There is no retry loop, new PageView server sender, new identity collection, backend deployment, or provider setting change.

## Tests and release boundaries

The new offline harness covers 28 cases, including all approved hosts, framed and unapproved origins, consent/native/private-route exclusions, queued work, catalog ID parity, browser/server event-ID equality, and no browser Purchase. Existing fixtures now explicitly model a top-level browser window. All network calls are mocked or forbidden.

Before release: focused harnesses, full critical runner, lint, typecheck, production-configured build, diagnostic baseline, secret scan, independent diff review and GitHub gates. Release only the exact clean merged site bundle; preserve the existing functions, entities, provider settings, native/Appflow release and ad drafts. Native execution already exits before tracking, so no native behavior or live-update release is requested by this web-only patch.

Rollback trigger: a verified consented top-level customer visit on an approved hostname cannot produce the existing Meta event sequence due to this guard. Use the exact prior web release, not an older unrelated snapshot; do not weaken consent or alter payment authority as a workaround.

## Unresolved measurement evidence

The PageView deduplication panel reports 42.42% coverage, but the current app server allowlist does not send PageView. Sampled activities include server PageViews on a public local-delivery landing page; the producing integration has not been identified. Do not blame Shopify or change its integration without evidence. This patch prevents new editor/preview emissions by the current application; it does not remove historical dataset activity or fix other independent senders.

No production Purchase, fake order, live payment or ad click was generated by this work. A browser event, a server receipt, deduplication and attributed sales remain separate verification gates. This change alone is not proof that C01's missing landing-page-view metric is resolved.
